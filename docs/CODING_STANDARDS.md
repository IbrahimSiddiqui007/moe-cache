# Coding standards

One page for anyone, or any session, building or testing moe-cache. It records what the repo already does and checks. Where a rule has a source, read the source.

| Area | Rule | Source to read |
|---|---|---|
| C++ in `src/` | One translation unit: `moe_cache_plugin.cpp` includes the `mc_*.inl` parts (each starts with a one-line "plugin part" comment and is not compiled alone). Plain-C++ headers (`mc_args.h`, `mc_tested.h`, `mc_rebalance.h`) have no ggml, so a test builds them alone. Names: `snake_case`, `mc_` prefix on parts, `MOE_CACHE_*` for environment switches. Comments say what is not obvious, often with the finding and where it came from (for example "found on the MSI Claw, RESULTS_LOG §50"). A switch is read once into a `static const` with `getenv`. Nothing may need more than ggml and the C++ standard library. Anything Windows-specific sits behind `plat::is_windows` or `#ifdef _WIN32` in `platform.h`; every change must still build on Linux and Windows (`build.sh --windows`) | `src/`, `build.sh`, `CONTRIBUTING.md` |
| Python in `bin/` `tools/` `planner/` | Standard library only (the import line of `bin/moe_cache.py` is the example; `tools/card_image.py` needs Pillow and Chrome and says so at the top). Functions and variables `snake_case`, internal state `_UPPER`. Launcher text goes through `say(msg, err=False)`, never bare `print`; messages start with `moe-cache:`, give the value found and what happens instead. Each file opens with a docstring: what it does, how to run it | `bin/moe_cache.py`, `tools/` |
| Hard rules the CI checks | The plugin compiles with both header sets (`third_party/ggml`, `third_party/ggml-v3`) under `-Wall -Werror`. No reading of ggml buffer struct fields (`buf->size`, `->buft`, ...): use the public API. The tested-ggml list in `src/mc_tested.h` is only changed with `tests/tested_ggml_test.cpp`. Python must compile; shell scripts must pass `bash -n` | `.github/workflows/quick.yml` |
| New speed work | Every switch is **off by default** until a paired run wins. Paired run = A B B A, same machine, clean (nothing else running). The text must be the same in meaning (the plugin never changes tokens; see `CONTRIBUTING.md`). Never read speed from a run with a sampler or profiler on. A change under 10 % needs both orders. A loser leaves the program: move it to `archive/` as a patch and add a row (switch, what it did, numbers, why archived, retest if) to `archive/README.md` | `archive/README.md`, `patches/llama.cpp/README.md` |
| llama.cpp patches | Base is the pinned release in `patches/llama.cpp/README.md`. One idea per patch, numbered `NNNN-short-name.patch`. Each has its own runtime switch, off by default. The plugin must still work on stock llama.cpp: nothing in `src/` may need a patch. Moving the pin means re-checking every patch with `tools/apply_llama_patches.sh` | `patches/llama.cpp/README.md` |
| Tests | Before a push run what `quick.yml` runs: `python3 -m py_compile bin/*.py tools/*.py tests/*.py planner/*.py`, both header-set compiles, `tests/args_test.cpp`, `tests/tested_ggml_test.cpp`, `tests/rebalance_test.cpp`, the model-free `tests/*_test.py` listed in the workflow, `bash -n` on scripts. Plugin changes also need `tests/identity.sh` on one MoE model (`CONTRIBUTING.md`). A new test is a file `tests/NAME_test.py` with a docstring that says how to run it; add it to the list in `quick.yml` if it needs no model. Launch plans have a golden file (`tests/launch_plan_golden*.json`): change it only when the launcher's output is meant to change, with `--record`, and say so in the commit | `.github/workflows/quick.yml`, `tests/` |
| Commits and branches | Message: `area: what changed (ID, switch, state)`, one line, for example `patches/llama.cpp: 0022 ... (GGML_VK_COUNT_EXPERTS_FAST, default off)`. Say "not measured" when it is not. One branch per session (`claude/NAME-xxxxxx`); it is merged into `experimental` only when its tests are green. `main` gets only tested, promoted work | `git log`, `CONTRIBUTING.md` |
| Numbers | A number in a README table comes from a run recorded in `docs/RESULTS_LOG.md` (and the current numbers in `docs/RESULTS.md`). Change the README table, `docs/benchmark_card.html` and the images (`python3 tools/card_image.py`) in one step. The baseline of that step must pass on a freshly restarted PC | `docs/benchmark_card.html`, `tools/card_image.py` |
| Text | Plain words. Lists go in tables. Only measured claims; mark anything else "not measured" or "untested". | `README.md` |
