# Configuration (environment variables)

**The first table is the list of common options; the second part ("Settings not listed above") covers every other `MOE_CACHE_*` name the code reads (175 in all).** `tools/env_names_check.py` checks that every name the code reads is mentioned in the docs. Defaults below are those of the code on 2026-11-03.

`moe-cache-server` and the control page set these for you. Moved here from the README on 2026-10-30, unchanged.


| Variable | Meaning |
|---|---|
| `MOE_CACHE_SIZE_GIB` | cache size in GiB, or `auto` (size from the memory limit) |
| `MOE_CACHE_RAM_GIB`, `MOE_CACHE_MARGIN_GIB` | override the detected memory limit; memory to keep free (default 1 GiB). The launcher's `--ram` sets `MOE_CACHE_RAM_GIB`: **it is a sizing hint for the cache, not a RAM cap** (Windows: no limit is set on the default path, see [WINDOWS.md](WINDOWS.md); Linux: the launcher sets no limit either, only a cgroup you set yourself, such as `systemd-run -p MemoryMax=` or a unit file, is a hard limit) |
| `MOE_CACHE_GGUF` | model file (split models: the first part) |
| `MOE_CACHE_PROFILE` / `MOE_CACHE_WARM` | learn expert usage here and warm-start from it / warm start only |
| `MOE_CACHE_STATS=1` | print hit rate, reads and evictions at exit |
| `MOE_CACHE_EXEC_FUSE=0` | turn off the fused gate+up executor job (on by default since 0.3.2: decode +0.3-2.6 % in every PC pair, same text; RESULTS 73) |
| `MOE_CACHE_IDLE_REBALANCE=0` | turn off the idle cache refill (on since 0.3.3: refills the RAM cache while an agent pauses; every PC pair won) |
| `MOE_CACHE_POLICY=classlru` | frequency-aware cache replacement instead of LRU (opt-in; on the miss-heavy 122B +1.3-2.9 % decode in every pair, on Flash-Next within noise; RESULTS 73) |
| `MOE_CACHE_STATS_SIGNAL=1` | print one `moe-cache-stats {json}` line of the running counters on request: Linux `kill -USR1 <pid>`, Windows set the named event `Local\moe-cache-stats-<pid>` |
| `MOE_CACHE_DISABLE=1` | load nothing: the server behaves exactly like stock |
| `MOE_CACHE_EXEC=0` | switch the expert executor off (default on) |
| `MOE_CACHE_EXEC_ECORES=N` | let the executor use N efficiency cores as well (the launcher sets up to 4 on hybrid Intel CPUs; `--no-ecores` to disable) |
| `MOE_CACHE_EXEC_THREADS=N`, `MOE_CACHE_EXEC_READERS=N` | compute threads (default: what llama.cpp asks for) and background reader threads (default 4) |
| `MOE_CACHE_EXEC_POOL_DECODE=1` | default off. With an explicit `-tb` different from `-t`, the executor pool is rebuilt once from the first single-token graph, so decode runs on `-t` threads (stock: the first graph, usually a prompt, sizes it). `MOE_CACHE_EXEC_THREADS` still wins. See docs/RAM_GUARD_AND_POOL_DESIGN.md |
| `MOE_CACHE_RAM_LOCK=1` | default off, Linux only. Locks the cache's private memory (mlock2 on fault) so the kernel cannot swap it. Needs `ulimit -l unlimited` / `LimitMEMLOCK=infinity`; if the limit is hit it says so once and carries on unlocked |
| `MOE_CACHE_DROP_READAHEAD=1` | default off, Linux only. After the startup fill, drops the model files' page cache copy (posix_fadvise DONTNEED). Not done in file-view mode (there the page cache is the cache) |
| `MOE_CACHE_GPU_SUM=0` | turn off the GPU sum: on by default since 2026-11-02, a long-prompt block also takes the router-weight multiply and the add chain after its last expert, so only their sum is read back (paired on the PC: 34k prompts +33 %, 128k +22 %, text byte-identical; `src/mc_device.inl`) |
| `MOE_CACHE_HOST_OUT=0` | turn off the direct copy of plugin outputs to the GPU (on by default; RESULTS 76) |
| `MOE_CACHE_EXEC_CHECK=1` | recompute every expert op the stock way and compare (slow; for testing) |
| `MOE_CACHE_TILED_CACHE=1` | audit idea D19, off by default, not measured: the duplicate-expert scan that decides whether llama.cpp would use its tiled routine runs once per ids tensor and graph run instead of for gate, up and down (same answer; per-op saving only for batches with 8+ picks) |
| `MOE_CACHE_FAST_KERNELS=0` | use llama.cpp's own Q2_0 kernel instead of the plugin's |
| `MOE_CACHE_IQ3_KERNEL=1` / `=0` | use the plugin's IQ3_XXS gather kernel (bit-identical) on any AVX2 CPU / turn it off; off by default on AMD, where gathers are slow (Zen 4: about 0.6x llama.cpp's own function) |
| `MOE_CACHE_ROUTE=skip` (`moe-cache-server --fast`; `--fast` also sets a q8_0 KV cache: KL 0.0045 alone on the laptop (CUDA), **0.0120 on the PC (Vulkan)**, `--fast` as shipped 0.0145 there; kept in `--fast` by the owner's choice, RESULTS 61 R11) | opt-in approximate routing: skip a low-ranked expert that is not in RAM. About +10-12 % when the model is much bigger than RAM; about 1 top token in 40-50 differs from stock (KL 0.005-0.012; RESULTS 31). Off by default |
| `MOE_CACHE_HYBRID=MiB\|auto` (`moe-cache-server --hybrid`) | opt-in, experimental: a bank of the most used experts (from the usage profile) in free GPU memory computes those picks while the CPU computes the rest. Flash-Next on 8 GB: 13.1 -> 17.4 tok/s; KL 0.0043 vs exact (about 1 top token in 60 differs). Needs a usage profile (the first session has none). The bank adapts to the session (`MOE_CACHE_HYBRID_ADAPT=N,K`, default 8,16; 0 = keep the profile choice). For models whose experts are slow on the CPU (IQ / Q2_0 quants); with Q4_K-class models such as Qwen3.6 it is slower than `--gpu-cache` (8.7 vs 15.7 tok/s at 12 GB). Off by default |
| `moe-cache-server --fast=kv` | only the q8_0 KV cache of `--fast`, every expert computed. **Chosen automatically** at `--ctx 131072` and above when a GPU is detected (or `--vram` is given) and you passed none of `--stock`, `--exact`, `--fast*`, `-ctk` / `-ctv`; with no GPU, or at lower context, it is opt-in. It may change answers. Passed the quality gate at 4k context (`docs/QUALITY_GATE.md`, level kv: KL 0.0079, top-1 96.7 %, tasks 190 = stock on Flash-Next Q2_0). At ctx 262144 the freed KV buys more GPU layers: prefill 2x, decode +11-13 % at 64k (RESULTS 72; that pair was measured when `-ub 1024` was the long-context choice; the launcher now picks `-ub 2048` above 32k context when it fits). |
| `MOE_CACHE_FEWER=N` (`moe-cache-server --fast=fewer` sets 2 and `--fast`) | opt-in approximate: on the CPU-held layers, decode and small batches never compute the N lowest-ranked experts of a token (at least half are kept). Passes the gate (level fewer: KL 0.034, top-1 92.0 %, tasks 192 vs 190); faster at 4k (+2-6 %), **unproven at 64k-256k** (decode pairs lost their values). Off by default |
| `MOE_CACHE_ROUTE_DROP=N`, `MOE_CACHE_ROUTE_KEEP=N` | with `ROUTE=skip`: how many of the lowest-ranked picks may be skipped (default 2; `--fast=2` sets 4, with at least half of the picks always kept) |
| `MOE_CACHE_COALESCE_MIB=N` | merge neighbouring expert reads of a long prompt into reads of up to N MiB (default 16; 0 = off). Flash-Next prefill +14-24 % |
| `MOE_CACHE_SCAN_TOKENS=N` | prompt batches of N+ tokens load experts at the evict-first end, so the cache from before a long prompt survives it (default 512; 0 = off). Flash-Next prefill +27 % |
| starter profiles (`moe-cache-server --no-starter` to skip) | with no usage profile yet, the launcher starts from the shipped one for the model family (`profiles/`): first request 2.1x faster on Flash-Next (RESULTS 53) |
| `MOE_CACHE_GPU_PACK=0` | turn off packing: by default a long-prompt block uploads only the experts its tokens use (exact; 70-token prompts 1.8x faster on Qwen3.6, RESULTS 52) |
| `MOE_CACHE_MAX_RAM_GB=N` | cap on the cache's memory in decimal GB (the launcher's `--max-ram`); 0 turns the default cap off (`src/mc_common.inl`) |
| `MOE_CACHE_WIN_VIEW=0` / `MOE_CACHE_LINUX_VIEW=0` | go back from the file-view cache (read-only views of the model file; the default on Windows since 2026-10-27 and on Linux since 2026-10-28) to private memory with direct reads |
| `MOE_CACHE_WIN_OPEN_HINT=sequential` / `random` | Windows A/B switch (WINDOWS-672, default off): open the model file view's handle with `FILE_FLAG_SEQUENTIAL_SCAN` or `FILE_FLAG_RANDOM_ACCESS`, which changes the cache manager's read-ahead for that file. Unset or anything else = the flags used before. Effect unknown (0-5 %, either sign): measure with an A B B A run before using it | Windows only |
| `MOE_CACHE_WIN_BUFFERED=0\|1\|2` | Windows private-memory path only: 0 unbuffered, 1 buffered through the file cache, 2 adds random-access hints (buffered is the default; see COMPATIBILITY.md) |
| `MOE_CACHE_HOST_RESERVE_MIB` | memory kept free for llama-server's prompt cache (`--cache-ram`); the launcher sets it |
| `MOE_CACHE_GUARD=1` | tests only: reading an evicted expert crashes instead of returning zeros (small models only) |


## Settings not listed above (checked against the code on 2026-11-03)

The table above is the short list. This part covers the remaining `MOE_CACHE_*` names the code reads, found with `tools/env_names_check.py` (it lists every name in `src/`, `bin/` and `planner/` and whether a doc mentions it; `--missing` shows only the gaps). "Who" says who should touch it: **everyone**, **advanced** (you know what the option does), **internal/testing** (for the project's own tests and experiments; leave alone), or **set by the launcher** (the launcher sets it for the plugin; do not set it by hand). Switch values: where a row says "1/on/true/yes", those four turn it on.

| Variable | What it does | Default | Who |
|---|---|---|---|
| `MOE_CACHE_ALLOW_SLEEP` | Lets the computer go to sleep while the server runs. Set to `1`, `true` or `yes` (same as `--allow-sleep`). Normally the launcher holds a sleep block so a long run is not cut off. | off (sleep is blocked while the server runs) | everyone |
| `MOE_CACHE_ASYNC_COALESCE` | Experimental: when background reads are queued, neighbouring experts in the file are fetched as one bigger read instead of several small ones. Any number above 0 turns it on. | off | internal/testing |
| `MOE_CACHE_CKPT` | Agent mode only (`--agent`): how many saved snapshots of the model's running state each conversation keeps, for models with recurrent layers. More snapshots use more RAM; fewer mean more re-reading of the prompt. Non-numeric values fall back to 8. Ignored if you pass the llama.cpp checkpoint flag yourself. | 8 | advanced |
| `MOE_CACHE_CLASSES` | Number of usage classes for the `classlru` cache policy (only used when `MOE_CACHE_POLICY=classlru`). Clamped to 2 to 8. Has no effect with the plain `lru` policy. | 4 | advanced |
| `MOE_CACHE_COMPUTE_DB` | Path to a JSON file of GPU working-memory sizes measured on your model (from llama-server logs). The planner can only raise its memory reserve from it, never lower it. A missing or damaged file is ignored. | off (built-in table only) | advanced |
| `MOE_CACHE_CPU_MASK` | Hex bitmask of CPUs (bit i = CPU i) the expert worker threads are pinned to. Overrides automatic pinning. Does nothing if `MOE_CACHE_CPU_PIN=off`. | unset (automatic on hybrid Intel CPUs) | set by the launcher |
| `MOE_CACHE_CXXFLAGS` | Build-time only, not read at run time: extra compiler flags for building the plugin. Mentioned in the code for `-DMOE_CACHE_NODE_PAD=1`, which pads each cache entry to its own cache line (about 40 bytes more per entry). | no extra flags (padding off) | internal/testing |
| `MOE_CACHE_DEMAND_FIRST` | Experimental: background guessed reads wait (up to about 5 ms) while reads the model is actually waiting for are queued, so guesses never delay needed experts. Any number above 0 turns it on. | off | internal/testing |
| `MOE_CACHE_E1_SAMPLE` | Windows-only diagnostic, used with `MOE_CACHE_E1_TIMES=1`: samples roughly every 15 ms what the main thread is doing between our graphs and reports it in the stats JSON. Any value (even empty) turns it on. | off | internal/testing |
| `MOE_CACHE_E1_TIMES` | Diagnostic timers that break down the gaps between graphs and the long-prompt GPU blocks. Only active together with `MOE_CACHE_SEG_TIMES=1`. | off | internal/testing |
| `MOE_CACHE_ECOQOS_OFF` | Windows only: set to `1` to stop Windows from throttling the process as a low-power one (EcoQoS) and from ignoring its timer requests. Does nothing on other systems. | off | advanced |
| `MOE_CACHE_ECORE_MASK` | Hex bitmask of efficiency cores the extra expert worker threads may use, for systems without Linux sysfs (Windows). Used together with `MOE_CACHE_EXEC_ECORES`, which says how many to use. | unset | set by the launcher |
| `MOE_CACHE_EVICT_SIBLINGS` | Experimental: when an expert is dropped from the cache, its other parts (gate, up, down) go too if idle, so an expert is whole or gone. Any number above 0 turns it on. | off | internal/testing |
| `MOE_CACHE_EXEC_FUSE_ANY` | Experimental: lets the gate and up matrices of an expert be computed together even when their weight types or row sizes differ. `1`, `on`, `true` or `yes` turn it on. | off | internal/testing |
| `MOE_CACHE_EXEC_SCRATCH` | Reuses per-thread working lists instead of allocating them for every small CPU batch. Set to `0` (or `off`/`false`/`no`) to turn it off. | on | internal/testing |
| `MOE_CACHE_EXEC_SHARE_IN` | Lets the gate and up matrices share one prepared copy of their input (same values, less work). Set to `0` (or `off`/`false`/`no`) to turn it off. | on | internal/testing |
| `MOE_CACHE_FIT_PARAMS` | Path to the `llama-fit-params` tool the planner uses to ask llama.cpp how much GPU memory it will reserve. Used if the file exists. | unset (looks next to llama-server, then on PATH) | advanced |
| `MOE_CACHE_GPU_BALANCE` | Experimental: when expert weights are split across GPU parts, hands out experts so each part gets a similar number of picks, not just a similar number of experts. `1`, `on`, `true` or `yes` turn it on. | off | internal/testing |
| `MOE_CACHE_GPU_BUCKET` | Experimental: rounds the GPU expert buffer size up to a multiple of N experts, so more blocks reuse the same graph shape (meant for use with `MOE_CACHE_GPU_TMPL`). Values below 1 count as 1. | off (1, no rounding) | internal/testing |
| `MOE_CACHE_GPU_CATCH` | Safety net, **Vulkan only**: if the GPU throws during an expert block (for example an allocation fails), the error is caught and the block runs on the CPU. On NVIDIA / CUDA a GPU error still ends the server: CUDA errors go to `GGML_ABORT` and `abort()` (llama.cpp b12064, `ggml-cuda.cu`), which no C++ catch stops. It has not yet met a real Vulkan failure (tested with `MOE_CACHE_GPU_CATCH=2`, a fake fault). After a lost device llama.cpp's own GPU layers fail too, outside this code. `0`/`off`/`false`/`no` turn it off. `2` throws a fake fault once, for tests. | on | internal/testing After a fallback the experts, and with `MOE_CACHE_GPU_SUM` (default on) also the router-weight multiply and the add of the experts, run on the CPU; stock and a run that never uses the GPU block do those two steps on the GPU, so the text can differ in later words from such a run (laptop test, Granite 1B, 4 of 4 prompts) and equals it with `MOE_CACHE_GPU_SUM=0`. | `MOE_CACHE_GPU_FREE_AFTER_PROMPT` | Off by default. `1` gives the long-prompt block's GPU buffer back (up to about one layer of experts) as soon as the prompt is over, so decoding and other programs have that video memory. The next long prompt allocates it again. |

| `MOE_CACHE_GPU_EVENTS` | Experimental: waits for the GPU result copy using an event instead of a full GPU synchronise. `1`, `on`, `true` or `yes` turn it on. | off | internal/testing |
| `MOE_CACHE_GPU_EXTRA_OPS` | Experimental: simple element-wise steps (clamp, scale) between expert matrices stay in the GPU block instead of sending the whole block back to the CPU. `1`, `on`, `true` or `yes` turn it on. | off | internal/testing |

### Names that are not run-time settings

These appear in the code but setting them in the environment does nothing (build-time macros, test build flags, shell variables inside the launcher script, or a name with no code behind it).

| Name | What it is |
|---|---|
| `MOE_CACHE_EXPORT` | Not an environment variable: an internal build macro that marks functions as exported from the plugin library. Nothing to set. |
| `MOE_CACHE_FEWER_RENORM` | Not read by any code. A comment says it is not implemented; setting it does nothing. See `MOE_CACHE_FEWER` and docs/QUALITY_GATE.md for the working feature. |
| `MOE_CACHE_LOAD` | Not a real environment variable. It is a shell array inside `bin/_moe_cache_env.sh` holding the settings (`LD_PRELOAD=...` plus `MOE_CACHE_PRELOAD=1`, or `GGML_BACKEND_PATH=...`) the launcher applies so llama-server loads the plugin. Do not set it. |
| `MOE_CACHE_METHOD` | Not a setting. The launcher script records here how the plugin is loaded into llama-server (`preload` or `path`) after it chooses. Test scripts read it. Setting it yourself has no effect on loading. |
| `MOE_CACHE_NODE_PAD` | Not an environment variable. It is a compile-time switch: build with `MOE_CACHE_CXXFLAGS=-DMOE_CACHE_NODE_PAD=1` to give each internal queue node its own CPU cache line (an experiment). Setting it at run time does nothing. |
| `MOE_CACHE_TESTED_GGML` | Not a runtime variable: a build-time setting (a C++ macro) listing the ggml versions this build was tested against. At startup the plugin prints a warning if your ggml is not in the list. Setting it in the environment does nothing. |
| `MOE_CACHE_TEST_MUTANT_ABI` | Not a runtime variable: a compile-time flag (`-D`) used only by CI to build a deliberately wrong plugin that expects another op number, to prove it refuses to run. Never set it. |
| `MOE_CACHE_TEST_MUTANT_DIRECT_SHARED` | Not a runtime variable: a compile-time flag (`-D`) used only by CI. It builds the plugin with an older, unsafe read path so the poisoned-reads test is proven able to fail. Never set it. |
| `MOE_CACHE_TEST_MUTANT_DUP_IDS` | Not a runtime variable: a compile-time flag (`-D`) used only by CI. It builds the plugin with the old duplicate-expert counting so `tests/dup_ids.sh` is proven able to fail. Never set it. |
| `MOE_CACHE_TEST_MUTANT_LAYOUT` | Not a runtime variable: a compile-time flag (`-D`) used only by CI to build a plugin that expects another struct layout, to prove it refuses to run. Never set it. |
| `MOE_CACHE_TEST_MUTANT_NO_EXEC_WAIT` | Not a runtime variable: a compile-time flag (`-D`) used only by CI. It removes a safety wait in the expert pool so the delayed-read test is proven able to fail. Never set it. |
| `MOE_CACHE_TEST_MUTANT_NO_STEPASIDE_WAIT` | Not a runtime variable: a compile-time flag (`-D`) used only by CI. It removes the waits before llama.cpp's CPU path so the delayed-read test is proven able to fail. Never set it. |
